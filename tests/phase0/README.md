# ManualBuilder フェーズ0 検証キット（Excel主出力検証版 / v0.4.16）

設計上の検証項目 **V-0〜V-19** を手元の Windows で確認するスクリプト一式です。

**目的は動くアプリを作ることではなく、「この設計で作って大丈夫か」を先に判定すること。**

---

## 使い方

zip を展開して **`run.cmd` をダブルクリック**してください。メニューが出ます。

`run.cmd` はファイルを変更せず、メニューだけを表示します。

最初にメニューの **0（着手可否ゲート）** を実行してください。ゲートは、ZIP由来の
Mark of the Web と UTF-8 BOM を変更前の状態で検査します。ブロック解除は配布元と
内容を確認できた場合だけ、ゲート末尾の確認に `y` と入力したときに実行されます。

### なぜ BOM を付け直すのか

**ダウンロード経路で BOM が失われることがあります。** PowerShell 5.1 は BOM のない UTF-8 を
Shift_JIS として読むため、日本語が壊れ、壊れた文字が引用符を飲み込んで構文エラーが連鎖します
（`繧ｹ繧ｯ繧ｷ繝ｧ` のような文字化けが出たらこれです）。

配布物の `.ps1` は UTF-8 BOM 付きです。`run.cmd` 自体は**全部ASCII**なので、
もしゲートで BOM 欠落が検出された場合も、先に原因を確認できます。

### UI/UX の確認

メニュー **17** で `uiux-preview.html` を開けます。これは製品版の情報設計・操作導線を
確認する静的プレビューで、Phase 0 の検証サーバとは別物です。判断理由と受入基準は
`UIUX-DIRECTION.md`、出力形式の要件は `EXPORT-REQUIREMENTS.md`、今回のコードレビュー結果は
`REVIEW-NOTES-v0.4.16.md` にまとめています。実機での再実行順は
`RETEST-v0.4.16.md` を参照してください。

## 各スクリプトの見どころ

### 00-gate-check.ps1 — 着手可否ゲート

`LanguageMode` の名前だけでなく、**実際に必要な8機能を1つずつ試します**
（`New-Object` / `HttpListener` / `Bitmap` / `Add-Type` / `Excel.Application` の型解決 /
`Word.Application` の型解決 / `FileSystemWatcher` / `Mutex`）。
モード名だけでは判断しきれないためです。

Excel の型解決失敗は主出力を作れないため着手不可とします。Word の型解決だけが
失敗した場合は、Word副出力を無効にしてExcel主出力の設計検証を続行できます。

### 04-word-layout.ps1 / 04-word-layout-supervisor.ps1 — Word副出力の安全確認

**V-4（ユーザーの Word を壊さないこと）が最優先です。** 他の失敗は「不便」で済みますが、
これの失敗は**未保存文書の消失**＝取り返しがつきません。

このスクリプトの V-4 実装:

```
1. 起動前の WINWORD PID 集合を記録
2. 1件でも存在すれば、COMを生成せずに中止
3. 0件の場合だけ New-Object -ComObject Word.Application
4. PIDを Hwnd で取得。取れなければ、起動後に新しく現れた唯一のPIDを採用
5. PIDが取れなくても、空ベースラインで得たCOM参照にだけ Quit() を呼ぶ
6. Stop-Process は、Hwndから直接特定した自PIDがQuit()後10秒経っても残る場合だけ
```

既存Wordと同時に出力できない制約はありますが、未保存文書を失うリスクを優先して採用します。
`-SimulateExisting` は Word を起動せずに、この中止分岐だけを安全に確認します。

通常は `04-word-layout.ps1` を直接実行せず、メニュー4〜7から監督スクリプト経由で実行します。
保存処理の直前・直後に `Word保存開始` / `Word保存完了` を表示します。90秒でタイムアウトした
場合、監督スクリプトは安全上WINWORDを強制終了しません。重要な文書がないことを確認して
PCを再起動し、`out\result-04-supervisor.txt` と最後の表示を共有してください。

#### 必ずやってほしい2パターン

| # | 手順 | 確認すること |
|---|---|---|
| 4-a-1 | Word を**閉じた**状態で メニュー4 | docxが1件生成され、監督判定がOK |
| 4-a-2 | メニュー4の成功後、Word を**閉じた**状態で メニュー5 | 10回すべて成功し、新しいWINWORDの残留なし |
| **4-b** | **Word で未保存の文書を開いた**状態で メニュー4 | **「Wordが起動中」と中止され、その文書がそのまま残る** |

4-b ではdocxが生成されないことが正しい動作です。

#### 生成された docx で目視確認すること

| # | 確認項目 |
|---|---|
| B-1 | 表紙のタイトルが大きく中央に出ているか |
| B-2 | 目次にページ番号付きで手順が並んでいるか |
| B-3 | 「手順 N ...」が見出しスタイルか（表示→ナビゲーションウィンドウ） |
| B-4 | 補足が囲み枠か。**奇数=段落罫線 / 偶数=1×1の表。どちらが好みか決めてください** |
| B-4 | **囲み枠の書式が次の段落に漏れていないか**（段落罫線側の弱点） |
| B-5 | 手順の見出し・説明・画像が別ページに分断されていないか |
| B-6 | 縦長画像がページに収まっているか（手順2・手順6） |
| B-7 | フッターにページ番号が出ているか |
| B-8 | 画像を右クリック→代替テキストの編集で文が入っているか |
| B-9 | **見出しも本文と同じフォントになっているか**（`NameFarEast` の効果） |
| B-11 | **表紙が1ページ目で、概要→手順1→6が順番どおりか** |
| B-12 | **手順2・5・6が見出し途中や本文途中から始まらず、必要時は見出し前で改ページされるか** |

### 08-server-min.ps1 — Word を一切起動しません

**V-10 の確認手順が要点です。**

1. サーバを起動してブラウザで開く
2. Win+Shift+S で撮る → 増えることを確認
3. **ブラウザのタブを閉じて30秒待つ**
4. その状態でスクショを3枚撮る
5. もう一度 `http://localhost:8765/` を開く
6. **その3枚が取り込まれていないことを確認**

6 が通れば「昼休みに撮った私用のスクショが夕方まとめて入る」事故を防げます。
コンソールに「基準時刻より前のため取り込みません」と出ます。
すべての操作が終わるまで、画面右上の「検証を終了」やコンソールの `Ctrl+C` は使わないでください。

### 09-excel-layout.ps1 / 09-excel-layout-supervisor.ps1 — Excel主出力

通常はスクリプトを直接実行せず、メニュー12〜15から監督付きで実行します。
最初はExcelをすべて閉じ、メニュー12だけを実行してください。成功時は
`out\excel\` にマクロなしのxlsxとレポートが生成されます。

既存Excelがある場合、所有PIDを安全に証明できなければ設定変更前に中止します。
既存プロセスへ `Quit()` や `Stop-Process` は行いません。タイムアウト時も監督側が
停止するのは子PowerShellだけです。

生成xlsxでは、目次、3シートの順序、リンク、各シートで1から始まる手順番号、
画像左・説明右の横長カード、画像の重なり、固定行、90%ズームを目視確認してください。
詳しい順番は `RETEST-v0.4.16.md` にあります。

### 07-html-size.ps1 — 旧HTML候補の技術データ

HTMLファイル出力はMVP対象外へ移しましたが、base64埋め込み方式の技術データとして
検証を残しています。base64 埋め込みは約33%増えるため、ステップが増えると単一HTMLが
実用外になります。
10 / 50 / 100 ステップで容量と生成時間を測り、`htmlEmbedLimitMB` の既定値（暫定25MB）を確定させます。

生成された HTML をブラウザで開いて、**体感の表示速度**と **Ctrl+P の印刷プレビューで手順が切れていないか**を確認してください。

## 注意

- `08-server-min.ps1` は `localhost` のみで待ち受けます。外部からは接続できません。
- 起動トークン ＋ `Host` ヘッダー検証 ＋ `Origin` ヘッダー検証を実装しています。
- 画像は一切外部に送信しません。すべて `out\` 配下のローカルファイルです。
- Officeを開いた状態を壊さないように設計していますが、Excel側は実機でX-10/X-11を
  通して初めて採用可と判断します。最初の検証はExcelを閉じて行ってください。
