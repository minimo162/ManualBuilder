# Word副出力の設計 v0.12

## 位置づけ

Excelを部内の主出力とし、Wordは縦方向に読み進める文書が必要な場合の副出力とする。同じ`project.json`を入力にするため、手順のあるシートの順序、手順順、文章、画像編集結果はExcelと一致する。

## 文書構造

1. 表紙 — 文書タイトル、`操作マニュアル`、作成日、ManualBuilder
2. 自動目次 — 手順のあるシートとその手順をWordの見出しから生成
3. シート — 見出し1。手順が0件のシートはWord本文と目次へ出力しない
4. 手順 — 見出し2。シート内で1から採番
5. 説明 — 通常本文
6. 補足 — 入力がある場合だけ淡い黄色の1セル表
7. 画像 — 切り抜き、赤枠、矢印、番号、黒塗りを合成した派生画像
8. フッター — 段落自体を中央揃えにしたページ番号

## デザイン

PC閲覧向けの簡潔なリファレンス文書を基準にする。

- A4縦、上下左右20mm
- BIZ UDPゴシックを優先し、利用できない場合はMeiryo等へフォールバック（アプリ・Excelと同じ解決順）
- 本文10.5pt、表紙タイトル28pt、見出し1は16pt、見出し2は13pt
- 見出しと本文の色はExcel出力と同一にする（見出し 58,91,160／本文 24,32,51／補足は淡い黄色）。
  同じproject.jsonから作る2つの出力で、テーマ色が食い違わないようにする
- 画像は段落中央へ配置し、縦横比を維持する
- 画像は最大450×510pt。小さな切り抜き画像は元の表示寸法から最大2倍まで拡大する
- 画像へ手順名の代替テキストを付与
- 段落罫線の書式漏れを避けるため、補足は1セル表へ統一

## 安全境界

- 起動前に`WINWORD`が1件でも存在すれば、Word COMを生成せず停止する
- 空のベースラインから作ったWordだけをPID差分で識別し、文書を追加した後の
  `ActiveWindow.Hwnd`が同じPIDを指すことを確認して所有を証明する
  （WordはExcelと違い`Application.Hwnd`が常に0のため、ActiveWindow経由で取得する）
- 所有PIDを確認してから`DisplayAlerts`等を変更する
- `Quit()`は作成用COM参照にだけ実行する
- `Stop-Process`はHwndで所有を証明したPIDにだけ許可する
- `.tmp.docx`へ保存し、保存完了と自己検査の後だけ完成名へ移動する
- 作成失敗時もプロジェクトと既存Word文書を変更しない
- 安全停止画面では、停止理由、影響がない対象、次の操作を別々に簡潔に表示する

## 自己検査

- 出力した手順数が入力件数と一致する
- 埋め込んだ画像数が画像付き手順数と一致する
- 空シート名が本文と目次へ混入しないことをCOM回帰テストで確認する
- 1920×1080画像が450pt幅で配置されることをdocx内部で確認する
- フッターのページ番号段落が中央揃えであることをdocx内部で確認する
- Wordが報告するページ数を結果へ記録する
