# ManualBuilder 出力・シート要件 v0.3

## 1. 製品方針

ManualBuilderは部内利用のマニュアル作成アプリとする。成果物の主形式はExcel、
副形式はWordとする。正式配布や印刷より、部内PCでの閲覧、追記、差し替え、
引継ぎのしやすさを優先する。

| 形式 | 位置付け | 主用途 |
|---|---|---|
| Excel | 主出力 | 部内で閲覧・追記・修正・引継ぎ |
| Word | 副出力 | Word形式が必要な場合、縦長文書として閲覧 |
| HTML | アプリ内プレビュー | 作成中の確認。独立ファイル出力はMVP対象外 |

アプリを正本とする。出力後のExcelまたはWordをアプリへ再取り込みする往復編集は
MVP対象外とする。

## 2. アプリ内の文書構造

プロジェクトは複数の「シート」を持ち、各シートが複数の手順を持つ。

```text
プロジェクト
├─ シート
│  ├─ 手順
│  ├─ 手順
│  └─ 手順
├─ シート
│  └─ 手順
└─ シート
```

シートはExcelのワークシート、Wordの章に対応する。
1手順を1ワークシートにはせず、ユーザーが業務上の区切りとして作ったシートだけを
ワークシートにする。手順数が増えてもタブが過剰に増えない構造とする。

### シート操作

- 新規プロジェクトには「手順1」シートを1件作る
- ユーザーはシートを追加、名前変更、並べ替え、複製、削除できる
- 削除は即時消去せず、同一セッション中は元に戻せる
- 撮影したスクリーンショットは、現在選択中のシート末尾へ追加する
- 手順は同一シート内および別シートへドラッグ移動できる
- 手順番号はシートごとに1から自動採番する
- シートを切り替えても、編集中の文字とスクロール位置を失わない

### シート名

- アプリ上は1～50文字
- Excel出力時は31文字へ短縮する
- Excelで使用できない `\ / ? * [ ] :` は全角または安全な文字へ置換する
- 同名になった場合は `名前 (2)` のように重複回避する
- 変換後のExcelシート名は出力完了画面で確認できる

## 3. Excel出力

マクロなしの `.xlsx` を生成する。アプリの各シートを同じ順序でExcelの
各ワークシートへ出力し、先頭にナビゲーション用の「目次」シートを置く。

### 目次シート

- 文書タイトル、版数、作成者、更新日
- シート名、概要、手順数
- 各ワークシートへのハイパーリンク
- 白基調で、業務上不要な装飾や表紙ページは置かない

### 手順シート

PCの横長画面で見ることを前提に、各手順を横長カードとして縦に並べる。

```text
┌────────────────────────────────────────────┐
│ 1  ログイン画面を開く                                      │
├──────────────────────┬─────────────────────┤
│                      │ 説明                                │
│      スクリーン      │ ブラウザを開き…                    │
│      ショット        │                                     │
│                      │ 補足                                │
│                      │ 社外からはVPNが必要                 │
└──────────────────────┴─────────────────────┘
```

- 左55～60%に画像、右40～45%にタイトル・説明・補足
- 画像の縦横比を維持し、カード領域内へ縮小する
- 画像はブックへ埋め込み、元ファイルへのリンクにしない
- 画像はセルとともに移動・サイズ変更する設定にする
- 説明と補足は通常のセルとして編集できる
- 補足は薄い黄色の背景と枠線
- BIZ UDPゴシックを優先し、なければMeiryo
- グリッド線を非表示にし、カード境界だけを薄い罫線で示す
- 先頭にシート名、概要、目次へ戻るリンクを置く
- 先頭行を固定し、既定ズームを90%とする
- 1366×768、表示倍率125%でも画像と説明の両方を確認できる
- 手順間に十分な余白を置き、セル全体を方眼紙のように見せない

### 印刷

印刷は副次要件とする。

- A4横、横1ページに収める設定だけ行う
- 手順ごとの強制改ページは既定で行わない
- 印刷ページ数の最小化や厳密なページ内配置はMVPの合格条件にしない
- 印刷レイアウトが必要な場合はWord出力を案内する

### 画像容量

- UI画面のスクリーンショットはPNGを基本とする
- 写真など色数が多い画像だけJPEGへ変換できる
- 同じ画像を目次用などへ重複埋め込みしない
- 50手順で50MB以内を目標、100手順では警告を表示する
- 元画像はアプリのプロジェクトに保持し、Excel用縮小画像と分ける

## 4. Word出力

Word出力は、同じシート・手順データを縦長文書へ変換する副出力とする。

- シートを「見出し1」、手順を「見出し2」とする
- 目次にはシートと手順を表示する
- シート順、手順順はExcelと一致させる
- 手順の見出し・説明・補足・画像を可能な限り同じページに置く
- 印刷品質の追求より、欠落・逆順・画像分離がないことを優先する
- Wordが起動中で安全な所有確認ができない場合は出力せず、Excelを案内する

## 5. 出力UI

ヘッダーの主ボタンは `Excelで作成` とする。その横のメニューから
`Wordで作成` を選べる。

出力ダイアログでは次を表示する。

1. Excel — 推奨。部内で閲覧・追記・修正
2. Word — 必要な場合だけ。縦長文書

HTMLは作成中のプレビューとして使い、MVPのファイル出力候補には表示しない。
最後に使用した形式を記憶するが、新規利用者の既定値は常にExcelとする。

## 6. Office COMの安全要件

- 起動前のOfficeプロセスを記録する
- 新しく生成したOfficeプロセスの所有権を確認してから設定変更する
- ユーザーが開いているExcelまたはWordへ `Quit()` や `Stop-Process` を実行しない
- 所有プロセスを証明できない場合は出力を開始しない
- 一時ファイルへ保存し、成功後に完成ファイル名へ移動する
- 未完成ファイルを成功扱いしない
- Word失敗時はExcel、Excel失敗時はアプリ内プレビューを案内する

Excelは部内で日常的に開いている可能性が高い。既存Excelが起動中でも、
新規COMインスタンスのPIDを安全に識別できるかをPhase 0で検証する。
識別できない場合は、既存Excelを閉じてから出力する安全制約を採用する。

## 7. 受入基準

| ID | 基準 |
|---|---|
| X-01 | アプリのシート順とExcelのワークシート順が一致する |
| X-02 | 各シート内の手順順が一致し、シートごとに1から採番される |
| X-03 | 撮影画像が選択中のシートだけへ追加される |
| X-04 | 手順を別シートへ移動しても、画像・タイトル・説明・補足が一緒に移動する |
| X-05 | 目次から各ワークシートへ移動でき、各シートから目次へ戻れる |
| X-06 | 1366×768・125%表示で、画像と説明を横並びで確認できる |
| X-07 | 画像の縦横比が保たれ、隣の手順カードへ重ならない |
| X-08 | シート名の禁止文字、31文字超、重複を安全に変換できる |
| X-09 | 50手順のブックを実用的な時間で作成・表示・保存できる |
| X-10 | 10回連続出力後に自分のEXCELプロセスが残留しない |
| X-11 | 既存の未保存Excelを開いた状態でも、その内容を失わない |
| X-12 | Word出力でもExcelと同じシート順・手順順になる |
| X-13 | 出力失敗時に未完成ファイルを成功扱いしない |

## 8. Phase 0で追加するExcel検証

1. Excel COMの起動、所有PID特定、保存、終了
2. 既存Excel起動中に別インスタンスを安全に識別できるか
3. 未保存Excelを開いた状態での生存確認
4. 3シート・画像6枚のPC閲覧レイアウト
5. シート名の禁止文字、長さ、重複変換
6. 目次リンク、固定行、ズーム、グリッド線非表示
7. 10回連続出力とEXCEL残留0
8. 50手順・100手順での作成時間、ファイル容量、操作感

`09-excel-layout.ps1` と監督スクリプトはv0.4.11で追加した。
Windows PowerShell 5.1とデスクトップ版Excelで単発、10回、キャンセル、
既存未保存ブック保護を実機検証してから、製品実装方式を確定する。
