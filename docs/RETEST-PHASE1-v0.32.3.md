# Phase 1 v0.32.3 再確認手順

v0.32.3は機能の追加ではなく、画面の使い勝手をひととおり見直した修正です。
どれも「動くが使えない」種類の欠けで、機能の試験では落ちないため、`docs/UIUX-DIRECTION.md`
の受入基準（UX-04・UX-08・UX-09・UX-10）と突き合わせて洗い出しました。

## 自動検査

Windowsで次を実行します。

```text
tests\phase1\run-tests.cmd
```

最後に `All Phase 1 foundation tests passed.` と表示されることを確認します。

## 目視確認

1. `run.cmd` からManualBuilderが起動し、マニュアル一覧と編集画面を開ける
2. 左の手順アウトラインで、説明が空の手順には塗りつぶしの目印、画像が無い手順には輪郭だけの目印が出る。入力済みの手順には目印が出ない
3. アウトラインの `⠿` にキーボードで移動し、`↑` `↓` を押すと手順が入れ替わる。中央のカードと番号も同時に変わり、離れても順序が保たれる
4. シート一覧の `⠿` でも同じように `↑` `↓` で並べ替えられる
5. シートを切り替えて戻ると、前に見ていたスクロール位置に戻る
6. `Tab` でボタンを移動すると、どのボタンにも輪郭線のフォーカス表示が出る
7. Windowsの「ハイコントラスト」を有効にしてもフォーカス位置が分かる
8. ウィンドウを幅620px以下まで狭めると、撮影監視の表示がアイコンだけになる。文字が途中で欠けた状態にならず、マウスを乗せると状態名が出る
9. 続けて2件以上の通知が出たとき、先に出た通知が消えずに積まれる。各通知の `×` で個別に閉じられる
10. Windowsの「アニメーションを表示する」をオフにすると、手順を選んだときの移動が滑らかな動きでなく即座に行われる
11. 画面左下の版数が `v0.32.3` になっている

## 修正内容

- 手順アウトラインの未完了の目印に `role="img"` を付け、読み上げへ届くようにした。
  「説明未入力」と「画像なし」は直し方が違うため、塗りと輪郭で形でも見分けられるようにした（UX-10）
- 並べ替えの取っ手に `↑` `↓` を割り当て、キーボードだけでも手順とシートを並べ替えられるようにした。
  保存経路はドラッグと同じものを使う（UX-08）
- シート切替時のスクロール位置の復元を有効にした。記録する処理だけがあり、戻す処理が呼ばれていなかった。
  差し替え直後は文書が短く位置が先頭へ丸められるため、届く高さになるまで数フレーム試す
- 幅620px以下で撮影監視の表示を要素ごと切っていたのをやめ、文言だけを畳むようにした。
  畳んだときも状態が分かるよう、ツールチップの先頭に状態名を置く（UX-04・UX-09）
- 通知を積んで出すようにし、閉じるボタンを付けた。エラーの表示時間を12秒へ延ばした。
  以前は次の通知が前の通知を消していたため、続けて起きた出来事の片方が読まれなかった
- フォーカス表示を影だけから輪郭線＋影へ変更し、ハイコントラスト時の指定を追加した
- 画面から作るダイアログすべてにアクセシブル名を付けた
- Copilotの進捗バーに現在値（`aria-valuenow`）を入れた
- 編集画面に画面上は見えない `h1` を置き、何を編集中かが読み上げの見出しから分かるようにした。
  あわせて `.sr-only` の幅指定がレイアウト用の指定に負けないようにした（負けると、見えないまま
  横スクロールが出る）
- `prefers-reduced-motion` の設定を、CSSだけでなく手順選択時のスクロールでも尊重するようにした
