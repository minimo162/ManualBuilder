# ManualBuilder UI/UX 方針 v0.5

## 結論

製品版は「高機能な文書エディタ」ではなく、**撮る → 一言書く → 次を撮る**を止めない
手順収集ツールとして設計する。Word や Excel のように自由配置させず、1ステップを
「番号・画像・タイトル・説明・補足」のカードに固定し、整形は出力時にアプリへ任せる。

部内利用ではExcelを正本ファイルとして扱う人が多いため、主出力はExcelとする。
Wordは同じデータから作れる副出力として残す。印刷より、PC画面で画像と説明を同時に
見られることを優先する。

Phase 0 の `08-server-min.ps1` は技術検証画面であり、製品UIの完成形ではない。
製品の方向性は `uiux-preview.html` で確認する。

## 1. 主役となる利用シーン

1. 新規マニュアルを作り、対象アプリへ切り替える。
2. `Win + Shift + S` で画面を撮る。
3. ManualBuilder に戻ると新しいステップが末尾へ入り、説明欄にフォーカスしている。
4. タイトルと説明を書き、`Ctrl + Enter` で確定して次の撮影へ進む。
5. 内容が変わる区切りではシートを追加し、現在のシートへ撮影を続ける。
6. 最後に全体をプレビューし、Excelを作成する。必要時だけWordを選ぶ。

平均的な作業では、ユーザーが触る主操作を「撮影」「説明入力」「出力」の3つに絞る。

## 2. 画面構成

### 編集画面

- 上部: 戻る、文書タイトル、保存状態、監視状態、プレビュー、作成ボタン
- 左: シートと、その配下のステップを表示する階層アウトライン
- 中央: ステップカード。画像と文章を同時に見られる主作業領域
- 右: 原則置かない。注釈編集時だけ一時的なツールパネルを出す
- 下部または空状態: 撮影、貼り付け、画像選択の入口

常設の設定や統計は主画面から外し、必要時だけ開く。検証用の受信件数やDPI情報を
製品画面へ持ち込まない。

### シート

- 左アウトライン上部に「シートを追加」を置く
- シート名をその場で変更できる
- シートをドラッグして並べ替えられる
- ステップを別シートへドラッグ移動できる
- 撮影画像は現在選択中のシート末尾へ追加する
- シートごとに手順番号を1から振り直す
- シート切替時は前シートの入力内容とスクロール位置を保持する
- Excel出力時はアプリのシートがそのままワークシートになることを画面内で示す

### ステップカード

- 番号は並べ替えに追随して自動採番する
- 画像を左、文章を右に置く。狭い画面では縦積みにする
- タイトルは1行、説明は複数行、補足は任意
- 順序変更はドラッグに加えて常設の上下ボタンでも操作できる
- 誤撮影の復旧頻度が高いため「削除」はカード上部へ常設し、確認後に実行する
- 「撮り直す」「複製」など低頻度操作は、実装時に常時見える `…` メニューへまとめる。画像編集は主要操作として常設する
- 画像はカード内で全体を確認し、クリック時だけ大きく表示する
- 自動保存中・保存済み・競合をカード単位で示す

### 集中表示とアウトライン

- 通常の入力作業は1手順だけを大きく表示する集中表示へ一本化する
- 左側に手順番号、短いタイトル、入力状態を並べ、長いページスクロールを避ける
- 入力済み、説明未入力、画像なしを色だけでなくツールチップでも示す
- 全体の順序確認、ドラッグ並べ替え、上下移動、削除は左アウトラインで行う
- 撮影直後は追加された手順を自動選択し、説明入力へ移動する

### 注釈

- カード画像の下に「画像を編集」を大きく常設し、切り抜き・赤枠・矢印・番号・黒塗りを明示する
- 作成した注釈は直後に選択状態へ切り替え、位置とサイズを続けて変更できる
- 切り抜きと注釈は変更後に自動保存し、保存状態を編集画面に表示する
- 赤枠、赤矢印、番号、黒塗りだけをMVPの常設ツールとする
- 画像そのものは変更せず、0〜1の比率座標をJSONへ保存して後から再編集できるようにする
- 選択後は移動、端点での大きさ調整、削除ができるようにする
- Undo／Redoを用意し、保存するまで元画像とプロジェクトを変更しない
- 黒塗りは元画像を保持するため、機密情報の完全削除ではないことを画面へ明記する

## 3. 視覚デザイン

- 基調: 白〜薄いグレー。業務画面のスクリーンショットが最も目立つ配色
- 主色: 落ち着いた青。主要操作と選択状態だけに使う
- 警告: 黄、エラー: 赤、成功: 緑。色だけに頼らずアイコンと文言を併記する
- 本文: 15〜16px。`BIZ UDPGothic` → `BIZ UDPゴシック` → `Meiryo` → `Yu Gothic UI`
- デスクトップの操作部品: 通常ボタン36px、アイコンボタン32pxを基準にする。主要ボタンはラベルを省略しない
- 一覧行は38px以上を確保し、フォーカスリングとキーボード操作を必須にする
- 角丸は6〜8pxを基準とし、カード常設の影とグラデーションは使わない
- 影はメニューやトーストなど、一時的に前面へ出る要素だけに使う
- 上部バー54px、左サイドバー224px、編集領域最大1800pxを基準にする
- 1920×1080・100%を標準、2560×1440・100%をワイド確認、実効1280×720を最低保証とする
- 1366×768はレイアウトが破綻しない範囲の互換対応とし、個別最適化の基準にはしない
- 空状態と通常状態に同じ主操作を重複配置せず、画面内の主CTAを1つに絞る

## 4. 状態の見せ方

### 撮影監視

ヘッダーに常時、次のいずれかを表示する。

- `監視中・このタブに追加`
- `閲覧専用・別タブが撮影対象`
- `一時停止・タブを閉じたため`
- `無効・保存先を検出できません`

状態の横に「なぜ」「どう直す」を1クリックで開ける案内を置く。監視停止中の画像を
後から勝手に取り込まない。

### 自動保存

- 入力中: 表示しない
- 通信中: `保存中…`
- 成功: `保存済み 14:32`
- 失敗: 入力内容を画面に残したまま `保存できません。再試行`
- 競合: どちらかを黙って上書きせず、相手の変更と自分の変更を選べる

### 出力

ヘッダーの主ボタンを `Excelで作成` とする。横のメニューからWordを選べる。
作成ダイアログでは形式名だけでなく用途も表示する。

- Excel（推奨）: 部内で閲覧・追記・修正する
- Word: Word形式が必要な場合に使う縦長文書

処理中は進捗、現在のステップ、中止を表示する。完了後は「開く」
「フォルダを開く」「もう一度作成」を提示する。

Word が使えない場合もエラーだけで終わらせず、同じ内容をExcelで作成する導線を出す。
Word が起動中の場合はWord作成を開始せず、「文書を保存してWordを閉じてから再実行」と表示する。
この状態でもExcel作成とアプリ内プレビューは利用できる。Excel出力も同様に、既存Excelを壊さない安全条件を
フェーズ0で確認してから有効化する。
Word出力が所定時間応答しない場合は「処理中」のまま放置せず中止可能にし、未完成ファイルを
完成品として表示しない。安全のため既存のWordプロセスは自動終了せず、Excel出力を提示する。

## 5. 機能の優先順位

### MVPで必須

- プロジェクト作成・自動保存
- スクリーンショット監視、貼り付け、ドラッグ&ドロップ、画像選択
- カード編集、並べ替え、削除と元に戻す、画像差し替え
- 連番バッジ、矢印、枠、黒塗りの注釈。ぼかしは用途検証後に追加
- ユーザーによるシート追加・名前変更・並べ替え・削除と元に戻す
- シート間のステップ移動
- Excel出力（シート別、PC閲覧向け横長カード）
- Word出力、出力前プレビュー
- 監視・保存・出力の状態表示
- 2タブ時の撮影対象／閲覧専用分離

### 後回し

- HTMLファイル出力、PDF直接出力
- テンプレート差し替え
- 章・分岐・共同編集・承認ワークフロー
- AIによる説明文生成

AIや自由レイアウトを先に入れると、核である撮影から出力までの信頼性検証がぼやける。

## 6. UI受入基準

| ID | 基準 |
|---|---|
| UX-01 | 初回利用者が説明なしで3分以内に「1枚撮影→説明入力→Excel作成」できる |
| UX-02 | 撮影後2秒以内に新規カードが見え、説明欄へ移動できる |
| UX-03 | 50ステップで一覧表示1秒以内、入力中の文字が部分更新で消えない |
| UX-04 | 監視状態と撮影対象タブが常に判別できる |
| UX-05 | 保存失敗時も入力内容を失わず、再試行できる |
| UX-06 | 削除・画像差し替え・注釈破棄を同一セッション中に元へ戻せる |
| UX-07 | Word失敗時にExcelへの代替導線が同じ画面に出る |
| UX-08 | キーボードだけでタイトル・説明入力と次カードへの移動ができる |
| UX-09 | 125% / 150% 表示倍率と1280px幅で主要操作が隠れない |
| UX-10 | 色覚に依存せず、状態が文言とアイコンでも伝わる |
| UX-11 | Word起動中はWord作成が無効になり、既存文書へ一切変更を加えない。Excelは作成できる |
| UX-12 | Word出力がタイムアウトした場合、未完成ファイルを成功扱いせず、Excelへの代替導線を表示する |
| UX-13 | 編集画面のシート・カード順とExcel/Wordの出力順が一致し、順序自己検査に失敗したファイルを完成扱いしない |
| UX-14 | Word出力では手順の見出し・説明・補足・画像を可能な限り同じページに置き、収まらない場合は見出し前で改ページする。見出しや本文先頭がページ外へ欠けた出力を成功扱いしない |
| UX-15 | Excelが推奨出力、Wordが副出力であることが拡張子の知識なしで分かる |
| UX-16 | Excel出力はアプリ上のシート順・手順順を保ち、画像・タイトル・説明・補足を同じ横長カードに配置する |
| UX-17 | シート追加後のスクリーンショットが、現在選択中のシートだけへ入る |
| UX-18 | ステップを別シートへ移動した際、番号が自動更新され入力内容を失わない |
| UX-19 | 1920×1080・100%をExcel表示の標準とし、2560×1440では余白を保ったまま画像と説明を同時に読める |

## 7. 実装上のUI原則

- htmx の部分更新対象はカード単位にし、入力中カードの親要素をポーリングで差し替えない
- 新規撮影は「新しいステップがあります」通知に留め、入力中は一覧全体を更新しない
- Sortable.js は並べ替え中に多重送信を止め、成功後に番号を再描画する
- JavaScript 無効時の完全動作は狙わないが、通常のフォーム送信で編集内容を救える構造にする
- 誤撮影の削除は主画面へ置くが、確認なしの完全削除にはしない。元に戻す実装後はゴミ箱から復元可能にする
- 注釈の黒塗りとぼかしは別機能として表示し、ぼかしを機密マスクと呼ばない
