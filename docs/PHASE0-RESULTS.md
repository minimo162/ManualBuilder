# ManualBuilder レビュー・実機結果 v0.4.16

## 総合判定

部内利用ではExcelで手順書を保守する利用者が多いため、Excelを主出力、Wordを副出力とする。
PC閲覧を優先し、Excelでは各手順を「画像左・説明右」の横長カードとして表示する。
アプリ内で利用者が作成したシートは、同じ順序のExcelワークシートへ出力する。

Word副出力は `手順書サンプル_r1_20260731_151718.docx` を再検証した。
一度は6ページ目の手順5が欠けているように見えたが、高精細レンダリングとPDFの文字座標を
確認すると、見出しと説明12行は通常の本文領域内にすべて存在した。表示ビューア上の
見え方による誤認であり、v0.4.10のWord出力は合格とする。

v0.4.11ではExcel主出力のPhase 0コードを追加した。Linux上ではExcel COMを実行できないため、
コード・構成・保存契約の静的検証までを本キット作成時に行い、X-01〜X-13の最終判定は
Windows PowerShell 5.1とデスクトップ版Excelで実行した結果に基づいて行う。

初回実機試験では、所有PIDをHwndから特定し、設定適用、Quit、EXCEL残留0まで合格した。
一方、`PageSetup.FitToPagesTall` の設定で例外となり、完成xlsxは生成されなかった。
v0.4.12では印刷設定を項目ごとのベストエフォートへ変更した。設定できない項目はWARNとして
記録するが、主目的であるPC閲覧用xlsxの生成は継続する。

v0.4.12の次の実機試験ではPageSetupを越えた後、Excelがシートまたはグラフ名を拒否した。
旧ログは処理段階を持たず、名前設定とリンク設定のどちらかを断定できなかった。
v0.4.13では禁止文字を中黒へ統一し、シート名の安全な代替、リンク失敗時の継続、
失敗段階と行番号のレポート出力を追加した。

v0.4.13は診断文字列の `$safeName:` がPowerShell 5.1で不正な変数参照となり、
workerが開始前にParserErrorで停止した。v0.4.14で`${safeName}:`へ修正し、
同種の通常変数＋コロンが09スクリプト内に残っていないことを静的確認した。

v0.4.14の実機試験では3件のシート名設定がすべて成功し、禁止文字変換と重複回避は通過した。
その直後、目次1行目の行番号を `Value2` へ代入する段階で、`Int32` から `String` への
キャスト例外が発生した。v0.4.15では数値を `Double`、文章を `String` へ明示変換する。
さらに目次のRange、Hyperlinks、Worksheetsを明示的に解放し、例外に伴うEXCEL残留を防ぐ。

v0.4.15の単発試験はX-01/X-02/X-05〜X-08/X-10/X-11/X-13がすべて合格し、
xlsx生成とEXCEL残留0を確認した。生成xlsxの構造では3件の目次リンク、3件の戻るリンク、
6画像、上部固定、グリッド線非表示、90%ズームを確認できた。一方、戻るリンクは
`Hyperlinks.Add`後に標準の青文字へ変わり、濃紺の見出し帯上で視認性が不足していた。
v0.4.16ではリンク追加後に白字・太字を再適用する。

v0.4.16の最終実機試験では、単発、10回連続、キャンセル、異常分岐がすべて合格した。
生成xlsxで戻るリンクの視認性を確認し、各ラウンドで完成ファイル生成とEXCEL残留0を確認した。
さらに既存Excelで未保存ブックを開いた状態でも、そのブックと入力内容に影響がないことを
利用者が確認した。以上により、Excel COM方式を主出力としてPhase 1へ採用する。

## 09-excel-layout.ps1 の実装

- マクロなし `.xlsx` を生成する
- 先頭に「目次」、続いてアプリ側の3シートを同じ順序で作る
- 各シート2手順、手順番号は各シートで1から再開する
- 目次から各シート、各シートから目次へハイパーリンクを付ける
- 禁止文字を全角へ置換し、31文字制限と `名前 (2)` の重複回避を行う
- 画像はリンクではなくブックへ埋め込み、縦横比を保持してカード内へ縮小する
- 左約57%を画像、右約43%を説明・補足にする
- 補足を薄い黄色、グリッド線非表示、ズーム90%、上部2行固定にする
- 印刷は副次要件としてA4横・横1ページの設定だけ行う
- 一時ファイルへ保存し、保存成功後だけ完成名へ移動する
- 目次リンク数、戻るリンク数、シート順、シート名、画像数を保存前に自己検査する

## Excel COMの安全設計

1. COM生成前に既存のEXCEL PIDを記録する。
2. `Application.Hwnd` から所有PIDを取得する。
3. Hwndが取れない場合、起動前のExcelが0件かつ新規PIDが1件だけなら所有PIDとして採用する。
4. 既存Excelへ接続した場合は設定変更前に中止し、`Quit()` を呼ばない。
5. 既存Excelがあり、所有PIDを証明できない場合も出力を中止する。
6. `Visible`、`DisplayAlerts`、`ScreenUpdating`、`EnableEvents` は所有確認後だけ変更する。
7. 強制終了は、Hwndで直接所有を証明したPIDが `Quit()` 後10秒残る場合だけに限定する。
8. 監督スクリプトのタイムアウト時は子PowerShellだけを停止し、EXCELを自動終了しない。

## 監督試験

`09-excel-layout-supervisor.ps1` は1回ずつ別のWindows PowerShell 5.1 STAプロセスで実行する。

- 単発: 完成xlsxが1件増え、EXCEL残留0であること
- 10回: 各回で完成xlsxが1件増え、毎回EXCEL残留0であること
- キャンセル: 完成xlsxが増えず、EXCEL残留0であること
- 異常分岐: Excelを起動せず、完成xlsxが増えないこと
- 既存Excel: 未保存ブックを変更せず、安全に中止するか、安全な別インスタンスで出力すること

## UI/UXの方向性

製品版はExcelを既定の主ボタンにする。Wordは隣のメニューから選べる副出力とする。
HTMLはアプリ内プレビューに使い、MVPの独立ファイル出力には含めない。

編集画面では、左にシート一覧、中央に手順カード、上部に現在のシート名と保存・出力状態を置く。
撮影したスクリーンショットは現在のシート末尾へ入り、同じカード内でタイトル、説明、補足を
入力する。シートと手順は並べ替えでき、別シートへの移動でも画像と文章を一体で扱う。

## Phase 0で完了した実機確認

1. メニュー0で全ps1のPowerShell 5.1構文解析とUTF-8 BOMが合格すること
2. Excelを閉じた状態の単発出力、xlsx生成、EXCEL残留0
3. 1366×768・Windows 125%で画像と説明を同時に読めること
4. 横長・縦長画像がカード外や次の手順へ重ならないこと
5. 目次リンクと「目次へ戻る」が動くこと
6. 10回連続出力、キャンセル、異常分岐
7. 既存の未保存Excelがそのまま残ること
8. Word副出力の安全性と基本体裁

50手順・100手順の時間、容量、操作感は、固定の6手順を使うPhase 0ではなく、製品データモデルを
実装するPhase 1で測定する。

## 採用判断

- Excel COM方式を主出力としてPhase 1へ進む
- 既存Excel起動中でも、所有PIDを証明できた別インスタンスだけで出力する
- 所有PIDを証明できない場合は、設定変更前に安全に中止する
- Wordは実出力確認まで合格しており、副出力として維持する
