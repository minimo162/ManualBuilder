# ManualBuilder Phase 1 v0.26.0 再確認

v0.26.0では、HTMLマニュアルを「あとから直せる」形にしました。あわせて出力ボタンの並びを変えました。

## 考え方

v0.25.0のHTML出力は、きれいに見えるかわりに直せませんでした。HTMLを直接編集するのは
一般の人には無理があり、かといって元データ（project.json）を別の場所で管理すると
「見る方を消しても容量が減らない」「元がどこにあるか分からない」という状態になります。

そこで、**1マニュアル＝1フォルダー**にしました。

```
営業システム操作マニュアル\
├─ マニュアルを開く.cmd     ← Edgeを指定して開く（IEモード対策）
├─ 編集する.cmd             ← 元データを取り込んでManualBuilderが開く
├─ index.html               ← ダブルクリックでも開ける
├─ images\                  ← 注釈と切り抜きを焼き込んだ画像
└─ _source\ [隠し]          ← 元データ（project.json・images・videos）
```

- フォルダーごとコピーすれば配れる。フォルダーごと消せば全部消える
- 動画は `_source\videos` の1本だけを持ち、HTMLはそこを参照する（二重に持たない）
- 直したい人は `編集する.cmd` を実行する。ManualBuilderが元データを取り込んで開く

出力先はこれまでどおり**ローカルのドキュメントフォルダー**です。共有フォルダーへは、
人がエクスプローラーでコピーします。ただし一度 `編集する.cmd` から編集した場合は、
どこから来たかを覚えているので、完了画面の「共有フォルダーへ反映」で更新できます。

## 運用の流れ

1. **作る人**: 「HTMLで作成」→ ローカルに出力 → フォルダーごと共有フォルダーへコピーする
2. **読む人**: 共有フォルダーの `マニュアルを開く.cmd` をダブルクリックする
3. **直す人**: 共有フォルダーの `編集する.cmd` をダブルクリック → ManualBuilderで直す
   → 「HTMLで作成」→ 完了画面の「共有フォルダーへ反映」を押す

3を何度繰り返してもManualBuilderのマニュアル一覧は増えません（同じIDなら既存を開きます）。

## 自動テスト

```powershell
tests\phase1\run-tests.cmd
```

## 目視確認

### 出力ボタンの並び（v0.26.0の変更）

1. 編集画面の右上に「Excelで作成」と「HTMLで作成」が**並んでいる**ことを確認する
2. 「…」メニューに「PowerPointで作成（動画つき）」と「Wordで作成」が残っていることを確認する

### Excelの完了画面の一言（v0.26.0の追加 → v0.27.0で置き換え）

v0.26.0では「動画はExcelには入りません」と案内していましたが、v0.27.0でExcelからも
動画を開けるようにしたため、この確認は不要です。
[docs/RETEST-PHASE1-v0.27.0.md](RETEST-PHASE1-v0.27.0.md) の該当項目を確認してください。

### HTML出力とフォルダーの中身

1. 「HTMLで作成」を実行し、「保存先を開く」でフォルダーを開く
2. 次を確認する
   - フォルダー名に**日付が付いていない**（マニュアル名だけ）
   - `index.html`、`images`、`マニュアルを開く.cmd`、`編集する.cmd` がある
   - 隠しファイルを表示すると `_source` があり、中に `project.json` がある
   - 動画を使っている場合、`_source\videos` に動画があり、`videos` フォルダーは**無い**
3. 「マニュアルを開く」でブラウザーが開き、動画つきの手順が**その場で再生できる**ことを確認する

### 同じ名前のフォルダーへの作り直し

1. もう一度「HTMLで作成」を実行する
2. 「すでにあります。最新の内容で作り直しますか？」と**確認が出る**ことを確認する
3. 「キャンセル」を選ぶと、フォルダーが**そのまま残る**ことを確認する
4. もう一度実行して「OK」を選び、内容が新しくなることを確認する
5. 出力フォルダーの中に `.mb-html-` や `.mb-old-` で始まるフォルダーが**残っていない**ことを確認する

### マニュアルを開く.cmd（IEモード対策）

1. 出力フォルダーを**フォルダーごと**共有フォルダーへコピーする
2. 共有フォルダーの `マニュアルを開く.cmd` をダブルクリックする
3. **Edgeで開く**ことを確認する（`index.html` を直接ダブルクリックすると
   組織のポリシー次第でInternet Explorerモードになることがあります。ここがその回避策です）
4. 画像が表示され、動画が再生できることを確認する

### 編集する.cmd と共有フォルダーへ反映

1. ManualBuilderを**終了**しておく
2. 共有フォルダーの `編集する.cmd` をダブルクリックする
3. 次を確認する
   - ManualBuilderが起動し、**そのマニュアルが開いた状態**になる
   - 手順・画像・注釈・動画が元のまま入っている
4. 手順名などを少し変える
5. 「HTMLで作成」を実行し、完了画面に次が出ることを確認する
   - 「反映先: \\\\共有フォルダー\\…\\マニュアル名」
   - 「共有フォルダーへ反映」ボタン
6. 「共有フォルダーへ反映」を押し、確認ダイアログで「OK」を選ぶ
7. 共有フォルダー側を開き、次を確認する
   - 変更した内容が反映されている
   - `.mb-publish-` や `.mb-old-` で始まるフォルダーが**残っていない**
8. もう一度 `編集する.cmd` を実行し、マニュアル一覧が**増えていない**ことを確認する

### 反映先を知らない場合

1. ManualBuilderで**新しく**作ったマニュアルを「HTMLで作成」する
2. 完了画面に「共有フォルダーへ反映」が**出ない**ことを確認する
   （最初の1回はエクスプローラーでコピーします）

### 共通

- 一覧または編集画面の左下／右下に `v0.26.0` と表示される
- Excel・Word・PowerPointの出力が従来どおり動く

## 補足: 開発時に確認済みの内容

HTML出力はCOMを使わないため、生成物は開発環境で完全に検証できました。

- `Test-HtmlExport.ps1`（77項目へ拡張）— 日付なしのフォルダー名、`_source` の同梱と隠し属性、
  動画が `_source/videos` の1本だけを指すこと、`.cmd` 2本の中身（Edge指定・`-ImportFrom`・
  `-PublishTo`・末尾が `\` のままの引数を渡さないこと）、同名フォルダーを黙って上書きしないこと、
  作り直しで古い中身が残らないこと、共有フォルダーへの反映が別名コピー→差し替えで行われること、
  反映先が反映元と同じ／中にある／届かない場合を断ること
- `Test-ProjectCatalog.ps1` — 反映先の記録が他の設定を消さないこと、同じマニュアルを
  何度取り込んでも一覧が増えないこと
- 実際のChromiumで生成HTMLを `file://` から開き、`_source/videos` の動画がその場で
  再生開始できることまで確認

実機では、**共有フォルダーからの `マニュアルを開く.cmd` と `編集する.cmd`** の確認をお願いします。
ここはネットワーク、ゾーン設定、Edgeのインストール先に依存するため、開発環境では再現できません。
