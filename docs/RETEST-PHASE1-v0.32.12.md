# Phase 1 v0.32.12 再確認手順

v0.32.12は、「操作を記録して手順にする」でUI Automationの通常経路から見つからない操作対象を、複数の経路で補う版です。

## 自動検査

Windowsで `tests\phase1\run-tests.cmd` を実行し、最後に `All Phase 1 foundation tests passed.` と表示されることを確認します。

## 操作対象の再検出

1. ManualBuilderを起動し、「操作を記録して手順にする」を開始する
2. EdgeまたはChromeで、メニュー、ダイアログ、候補リストなどクリック後にフォーカスが移る要素を操作する
3. ページ内に重ねて表示されるポップアップや、UI Automationの別枝として公開されるボタン・リンクを操作する
4. Win32の旧式アプリや独自業務アプリで、ボタン、リンク、チェックボックス、入力欄を操作する
5. 記録を停止して取り込み、操作対象の名前と赤枠が実際の要素に一致することを確認する
6. 操作パターンを持たない説明文や、ウィンドウ全体に赤枠が付かないことを確認する
7. UIAとMSAAのどちらも対象情報を公開しないCanvasやリモートデスクトップでは、クリック位置の小さな枠が残ることを確認する

## 今回の検索順

- クリック点と周辺点から取得したUI Automation要素とその親
- クリック点を含むDocument・Pane・Groupの表示中の子孫
- クリック後にフォーカスされたUI Automation要素
- 前面ウィンドウのHWNDから取り直したUI Automation全枝
- WindowsのMSAA（AccessibleObjectFromPoint）
- 名前付きUIA要素の推定、最後にクリック位置の小さな枠

すべての経路でクリック点を含む矩形だけを採用し、ウィンドウ面積の40%を超える推定・MSAA対象は除外します。
