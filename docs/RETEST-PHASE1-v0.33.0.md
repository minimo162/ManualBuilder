# Phase 1 v0.33.0 再確認手順

## 目的

「操作を記録して手順にする」で記録用Edgeを使い、画面遷移前のWeb要素をDOMから取得して赤枠と操作対象へ反映できることを確認します。

## 事前準備

1. Windows 10または11で、Microsoft Edgeがインストールされた環境を使います。
2. `run.cmd` でManualBuilderを起動します。
3. テスト用Webページとして、リンク、ボタン、入力欄、プルダウン、画面遷移するボタン、クリックで閉じるメニューがあるページを用意します。

## 記録用Edge

1. その他メニューから［操作を記録して手順にする］を開きます。
2. ［記録用Edgeを使う（推奨）］が選択されていることを確認します。
3. ［記録を開始］を押し、別ウィンドウで記録用Edgeが開くことを確認します。
4. 記録用Edgeでリンク、ボタン、入力欄、プルダウンを順に操作します。
5. 画面遷移するボタンと、押すと消えるメニュー項目を操作します。
6. ManualBuilderへ戻り、［記録を終了］を押します。

期待結果:

- リンクやボタンの実際の表示名が操作対象になる。
- 赤枠がページ全体ではなく、押した要素の矩形へ付く。
- 画面遷移するボタンと消えるメニューも、遷移・消滅前の要素として特定される。
- 確認一覧でDOMから取得した操作に「Edgeで特定」と表示される。
- 入力したキーそのものは保存されず、画面に写った文字は自動で黒塗りされない。

## 表示倍率と複数モニター

1. Edgeの表示倍率を125%または150%へ変更して記録します。
2. 記録用Edgeを別のモニターへ移動して記録します。

期待結果:

- どちらの場合も赤枠が操作対象から大きくずれない。

## フォールバック

1. ［その他のアプリを記録する］を選び、Windowsアプリを操作します。
2. 記録用Edgeで、DOMを取得できないブラウザー内部画面などを操作します。

期待結果:

- Windowsアプリは従来どおりUI Automation／MSAAで対象を特定する。
- DOMを取得できない操作でも記録は止まらず、Windowsの検出または小さなクリック位置枠へ切り替わる。

## 終了とプロファイル

1. 記録を終了またはダイアログを閉じます。
2. 記録用Edgeが閉じることを確認します。
3. 再度記録を開始し、記録用Edgeのログイン状態が引き継がれることを確認します。

## 自動テスト

Windows PowerShell 5.1で次を実行します。

```powershell
tests\phase1\run-tests.cmd
```

PowerShell構文、UTF-8 BOM、DOM座標変換、必須ファイル、バージョン表記がすべて `[OK]` になることを確認します。
