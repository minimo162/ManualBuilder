# ManualBuilder Phase 1 v0.22.0 再確認

v0.22.0では、注釈が1件だけの手順で注釈が失われる不具合、Word出力後にWINWORDが残る不具合、
応答の送信中にサーバーが停止する不具合を修正しました。番号注釈の採番も変更しています。
以下は配布前に実機で確かめる項目です。

```powershell
tests\phase1\run-tests.cmd
```

Excelをすべて閉じてから、次も実行します。

```powershell
tests\phase1\run-excel-test.cmd
```

Wordをすべて閉じてから、次も実行します。

```powershell
tests\phase1\run-word-test.cmd
```

## 目視確認

### 注釈が1件だけの手順（v0.22.0の主要な修正）

以前は、注釈がちょうど1件のときだけ編集画面から注釈が消え、そのまま画像編集を保存すると
元の注釈が失われていました。Excel出力には出るため、画面と出力が食い違う状態でした。

1. 画像付きの手順を1つ用意し、赤枠か番号を**1つだけ**付けて画像編集を閉じる
2. 別のシートや手順へ移動し、元の手順へ戻る（または `run.cmd` で開き直す）
3. 次を確認する
   - 画像の上に注釈が**表示されている**
   - 「画像を編集」の横のバッジが `注釈 1` になっている
   - もう一度「画像を編集」を開くと、**その注釈が残っている**
   - 何も足さずに閉じても、注釈が消えない
4. 注釈を2件以上にした場合も同じように表示・保存されることを確認する

### Word出力とプロセス残留

以前は、Word出力のたびに `WINWORD.EXE` が残っていました。

1. Wordをすべて閉じる。タスクマネージャーの「詳細」で `WINWORD.EXE` が無いことを確認する
2. その他メニューの「Wordで作成」を実行し、完了させる
3. 出力後に `WINWORD.EXE` が**残っていない**ことを確認する
4. 出力したdocxを開き、次を確認する
   - 表紙・目次・見出し・画像・フッターのページ番号が従来どおり
   - 見出しの青と本文の色がExcel出力と同じ系統に見える

### 番号注釈

番号は、同じシートの手順をまたいで連番になります。シートが変わると1へ戻ります。

1. 同じシートの手順1に番号注釈を付ける（`1` になる）
2. 同じシートの手順2に番号注釈を付ける → **`2` から続く**（以前は毎回 `1` に戻っていた）
3. 別のシートの手順に番号注釈を付ける → **`1` へ戻る**
4. 付けた番号をクリックして選び、ツールバーの「番号の値」へ任意の数字を入れる
   - `1`〜`99` の範囲で変更でき、バッジの数字がその場で変わる
   - 範囲外（`0` や `150`）は受け付けず、元の値へ戻る
   - Enterで確定しても編集画面は閉じない
5. Excel／Wordへ出力し、画面で見えていた番号がそのまま出ることを確認する

### Excel出力の見た目

1. **画像のない手順**を含むマニュアルでExcelを作成する
2. 次を確認する
   - 画像のない手順は、左半分が空かず**説明と補足がカード全幅**で表示される
   - 説明が短い手順でも、文章側がグレーと白に分かれず**白の一枚面**になっている
   - 説明と補足の文字が、画像との区切り線に張り付かず少し字下げされている
   - 画像付きの手順は従来どおり、画像が左・説明が右で半分ずつ

### 共通

- 一覧または編集画面の左下／右下に `v0.22.0` と表示される
- 一覧画面の見出し上のラベルが `作成したマニュアル` になっている
- 画面の文字が BIZ UDPゴシックで表示され、極端に細い／太い箇所が無い

## 補足: 開発時に確認済みの内容

架空のサンプル（2シート5手順・注釈4種・画像なし手順を含む）で次を確認済みです。
実機では上の手順で追認してください。

- 注釈1件の手順が編集画面に表示され、`project.json` に保持されること
- Word出力の所有モードが `Hwnd` になり、出力後の `WINWORD.EXE` が0件であること
- Word出力の余白20mm・表題28pt・見出し16／13pt・本文10.5pt・画像450pt幅・
  フッター中央揃えが設計どおりで、見出しと本文の色がExcelと一致すること
- 番号注釈がシート内で連番になり、任意の値へ変更した結果が保存されること

なお、応答の送信中にサーバーが停止する不具合（大きな画像やZIPのダウンロードを中断した場合）は
コード上の対処のみで、再現手順を伴う自動テストは用意していません。
ダウンロードを途中で中止しても画面が使い続けられることを、気づいたときに確認してください。
