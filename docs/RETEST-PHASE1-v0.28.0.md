# Phase 1基盤 v0.28.0 再確認手順

録画を1本渡すと、場面ごとに手順が並び、押された場所に赤枠が付き、
Microsoft 365 Copilot が手順名と説明の下書きを作るところまでを確認します。

前提: Windows 10/11・PowerShell 5.1・Microsoft Edge・Microsoft 365 Copilot を使える職場アカウント。
管理者権限は要りません。

---

## 0. 事前準備

1. `tests\phase1\run-tests.cmd` を実行し、すべて成功することを確認する。
   - `Test-CopilotDraft.ps1` が新しく加わっています。
   - Node がある環境では `Test-VideoScenes.mjs` も走ります。無い環境では `[SKIP]` と出ます。
2. 録画を1本用意する。次の条件を満たすものが確認に向きます。
   - 3〜5回、画面がはっきり切り替わる操作が入っている（ボタンを押す、タブを切り替える等）
   - 1つの画面で1秒以上止まっている

---

## 1. 録画から手順を自動で作る

1. `run.cmd` でManualBuilderを開き、マニュアルを新規作成する。
2. 手順の追加から録画（mp4またはwebm）を選び、「動画から手順を作る」を開く。
3. **［自動で手順に分ける］** を押す。

確認すること:

| # | 確認内容 | 期待 |
|---|----------|------|
| 1-1 | 進捗の表示 | 「場面の切れ目を探しています」→「操作された場所を調べています」→「画面を取り込んでいます」→「手順にしています」と進む |
| 1-2 | 作られた手順の数 | 画面が切り替わった回数とおおよそ一致する。遷移の途中のコマが手順になっていない |
| 1-3 | 代表のコマ | 各手順の画像が、画面の描画が終わった後の状態になっている（読み込み中やフェード途中でない） |
| 1-4 | 赤枠 | 押されたボタンのあたりに赤枠が付いている |
| 1-5 | 同じ画面 | ツールチップが出ただけ、といった場面で手順が二重に作られていない |
| 1-6 | 中止 | 処理中に×で閉じると、シークの繰り返しが止まる |

**赤枠が付かない場合があります。** 画面全体が一度に切り替わった手順では、押された場所を
特定できないため枠を出しません。これは想定どおりの動作です（憶測の枠を出さない方針）。

### 1-7. 文字認識の効き方

Windowsの文字認識が使える環境では、赤枠がボタンの輪郭に沿って締まります。
使えない環境では、録画の変化だけで決めた枠（やや大きめ）になります。
どちらの環境でも手順づくりは最後まで進みます。

確認方法: Copilotの画面（後述）を開いたとき、上部に
「画面の文字を読み取って赤枠と操作対象を補います。」と出れば有効です。

## 2. Copilotで手順の文章を作る

1. 右上の […] メニューから **［Copilotで手順の文章を作る］** を選ぶ。
2. 初回は **［Copilotの画面を開く］** を押し、Edgeが開いたらサインインしてから戻る。
3. **［下書きを作る］** を押す。

確認すること:

| # | 確認内容 | 期待 |
|---|----------|------|
| 2-1 | 注意書き | 画像がMicrosoft 365 Copilotへ添付されることが最初に書かれている |
| 2-2 | 進捗 | 「画面をCopilotへ渡しています（1/3）」のようにまとまりごとに進む |
| 2-3 | 編集の継続 | 下書きの最中でも、ManualBuilderの編集画面を操作できる |
| 2-4 | 中止 | ［中止］を押すと、その時点までの下書きで止まる |
| 2-5 | サインイン切れ | サインアウト状態で実行すると「サインインが必要です」と案内が出る |

### 2-6. 下書きの内容

出来上がった下書きを見て、次を確認します。

- 赤枠のボタン名が説明に入っている（例:「「申請」を選択します。」）
- 「画面の指示に従って入力します」のような、どの画面にも当てはまる文になっていない
- すでに文章を書いた手順は、既定では対象になっていない

---

## 3. 確認画面での採用

| # | 確認内容 | 期待 |
|---|----------|------|
| 3-1 | 既定のチェック | 「自信なし」「不要かもしれません」が付いた下書きは、最初からチェックが外れている |
| 3-2 | その場での修正 | 手順名・説明・補足をその場で直してから採用できる |
| 3-3 | 採用 | ［選んだ手順に入れる］で、チェックした手順にだけ文章が入る |
| 3-4 | 却下 | チェックを外した手順の文章が変わっていない |
| 3-5 | 閉じる | 採用せずに閉じると、次に開いたとき前回の下書きが残っていない |

**重要な確認（3-6）**: すでに文章がある手順に対して「すでに文章を書いた手順も対象にする」を
選んで下書きを作り、確認画面で手順名だけを空にして採用します。
このとき **説明が消えず、元のまま残る** ことを確認してください。
空欄は「変更しない」の意味であり、消去ではありません。

新しい項目（`capture`）を手順へ追加したため、既存の出力を一通り確認します。

| # | 確認内容 | 期待 |
|---|----------|------|
| 4-1 | 旧マニュアル | v0.27.3以前に作ったマニュアルを開いても壊れない |
| 4-2 | Excel出力 | 従来どおり作成できる |
| 4-3 | Word出力 | 従来どおり作成できる |
| 4-4 | PowerPoint出力 | 従来どおり作成できる |
| 4-5 | HTML出力 | 従来どおり作成できる |
| 4-6 | 出力の中身 | 録画由来の情報（読み取った画面の文字など）が出力に出ていない |
| 4-7 | ZIP書き出し・取込み | 従来どおり動く |
