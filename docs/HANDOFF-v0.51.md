# ManualBuilder v0.51 引き継ぎ書

更新日: 2026-08-08

対象ブランチ: `codex/copilot-timeline-frames`

基点: `main` / `f81cf7e`（Improve recorded manual workflow #47）

## 1. 現在の製品方針

ManualBuilderは「AIが自動で正しいマニュアルを完成させるアプリ」ではない。

現在の価値提案は次の一本に絞っている。

> 普段どおり操作する → 要確認だけ直す → Excel手順書を作る

内部では元の操作証拠と変換理由を保持するが、通常の利用者へ全件の技術情報を見せない。高確度候補は自動採用し、不確実な候補と既知の記録欠落だけを確認対象にする。

主出力はExcel、印刷向けの副出力はWord。データはローカルPC内に置き、公開・共有は完成ファイルを利用者が手動で行う。Copilotや外部AIは通常導線で使用しない。

## 2. 利用者の標準導線

1. 空の編集画面で［操作を記録して始める］を押す。
2. 機密情報と通知が画面画像に写ることを確認して［記録を開始］を押す。
3. Edge、Excel、エクスプローラーなどで普段どおり作業する。
4. 対象アプリの端に表示される「記録レシート」で、直前画像の確認・取消・結果画像の追加・終了を行う。
5. 記録終了後、高確度候補は自動採用される。要確認がある場合だけ、手順名・説明・画像・赤枠を確認して［使う／除外］を決める。
6. 編集画面で必要な微修正を行い、［Excelを作成］から出力する。

操作前画像が主画像である。操作後画像は結果確認が必要な手順だけに使い、初見の全手順へ前後2枚を強制しない。

## 3. 今回実装した主要機能

### 操作証拠形式 v2

- 記録開始、各操作、記録欠落、取消、記録終了をJSONL台帳へ追記する。
- 各操作に不変の `evidenceId` と証拠画像を付ける。
- 作業用イベントを取り消しても元証拠は削除せず、取消判断を追記する。
- プロジェクトへ取り込むと `evidence/<record-id>/` 以下へ台帳・画像・変換履歴を保存する。
- 手順から `sourceSessionId`、`evidenceIds`、元操作件数、変換理由を辿れる。
- マウス／キーボードフック停止やキューあふれを `capture-gap` として残し、黙って成功扱いにしない。

互換性は不要という決定のため、旧操作証拠形式を推測して取り込む処理は持たない。`capture-start` と `capture-end` が形式v2で揃い、全証拠画像が存在する場合だけ取り込む。旧記録は新しい版で記録し直す。

### ローカル候補生成

- クリック／入力時刻と前後の安定フレームから候補を作る。
- 操作後画像が次の操作時刻を越えないよう境界を制限した。
- 入力欄クリックと直後の入力を1手順へ統合する。
- キーボードとマウスを記録時刻順に処理し、高負荷時の入力分裂・ウィンドウ誤帰属・時系列逆転を防いだ。
- DOM、OCR、クリック点だけの候補は自動確定しない。
- UI Automation / UIAキャッシュの対象名・矩形・クリック点が独立に一致した非入力操作だけを高確度へ昇格する。
- 入力値やExcelエラーをOCRが項目名として読んだ場合は、安全な汎用文言へ退避し、プロジェクトの非表示メタデータにも残さない。
- 候補IDは候補の根拠から決まる固定ID。確認画面と取り込み処理で同じ候補を追跡できる。

### 短い例外レビュー

- 既定表示は「要確認のみ」。全候補は詳細操作から開く。
- 要確認候補は、取り込む前に手順名と説明を直接修正できる。
- チェックボックスではなく［この手順を使う／除外しました］で採否を示す。
- 採用・除外・文章修正・利用者確認を `transformations.jsonl` へ追記する。
- 記録欠落が既知または完全性不明なら、自動取り込みせず全候補を要確認にする。
- 変換理由と元操作件数は［元の操作を見る］の詳細へ下げた。

### 記録レシート

- WPFの標準WebView2を使う独立した記録補助画面。専用ブラウザープロファイルは使用しない。
- 通常時は操作の邪魔を抑え、画像確認時だけ大きなプレビューへ切り替える。
- 直前画像、取消、結果画像追加、一時停止、終了をManualBuilderへ戻らず操作できる。
- BIZ UDPゴシック、角丸、配置、配色をHTML/CSS側で統一した。
- 記録レシート自身を操作画像へ混ぜない。

## 6. 未実施・既知の制約

### 実Excel COM出力の再実行

このPCでは、所有不明の既存Excelプロセス（検証時PID 38804）が起動していた。未保存ブックへ触れない安全設計を守り、終了や新規COM出力試験を強制していない。

`tests/phase1/Test-ExcelExport.ps1` は証拠形式v2のセッションと手順由来情報を含むよう更新済み。Excelをすべて閉じられるときに次を実行する。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\phase1\Test-ExcelExport.ps1
```

### 新規の高負荷実機録画

今回のCodex環境ではWindows操作権限が `EPERM` になり、Computer Useと安全ハーネスの前面化が使えなかった。既存の実Excel／Edge録画と自動テストでは改善を確認したが、次回は通常ユーザーセッションで以下を再試験するとよい。

- Edgeで検索・遅延結果・新規タブを操作する。
- Excelへ切り替え、複数セル入力、数式、範囲選択、表示形式変更を行う。
- Edgeへ戻り、検索条件を解除する。
- 欠落、重複、遷移中画像、別対象の赤枠が0であることを確認する。
- 要確認だけ直し、Excelを作成して閲覧する。

### 残る技術負債

- Copilot関連モジュールと動画取込みは過去機能の実装がソースに残る。ただし通常の操作記録導線から外部AIを呼ばない。次に大規模整理する場合は、利用実態を確認して機能単位で削除する。
- プロジェクト全般の旧データ移行処理は、今回廃止した「旧操作証拠形式」とは別物。これも不要と決定する場合は、保存データの削除範囲を明示して別PRで扱う。
- UIAが得られない入力とOCR候補は安全上要確認が多い。確認件数を減らす場合も、DOM/OCRを無条件で高確度にしない。

## 7. 再開時の優先順

1. Excelを閉じられる環境で `Test-ExcelExport.ps1` を完走する。
2. 上記のEdge→Excel→Edge実機シナリオを3回記録し、候補数・順序・赤枠・after画像を採点する。
3. 初見の一般事務職へ「説明なしで記録からExcelまで」を試してもらい、操作時間と迷った箇所を記録する。
4. 精度改善は、欠落した操作の回収を最優先にする。文章の自動整形やAI再導入は、ローカル記録品質が安定するまで主導線へ戻さない。

## 8. 起動とテスト

通常起動:

```powershell
.\run.cmd
```

全回帰テスト:

```powershell
$env:CI = '1'
.\tests\phase1\run-tests.cmd
```

変更後に通常版が古い画面を表示する場合はManualBuilderを終了し、再起動する。ソース確認用の隔離サーバーや検証用ブラウザータブは作業終了時に停止済み。
