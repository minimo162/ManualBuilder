# Phase 1 v0.32.9 再確認手順

v0.32.9は、「操作を記録して手順にする」の対象検出を再調整し、入力欄の自動黒塗りを手動マスクへ変更した版です。

## 自動検査

Windowsで次を実行します。

```text
tests\phase1\run-tests.cmd
```

最後に `All Phase 1 foundation tests passed.` と表示されることを確認します。

## 操作対象の確認

1. `run.cmd` からManualBuilderを起動する
2. その他メニューから「操作を記録して手順にする」を開始する
3. EdgeまたはChromeで、長いページの上部・中央・下部にあるリンクをクリックする
4. 文字部分、余白部分、アイコン部分を変えて同じボタンをクリックする
5. ボタン、チェックボックス、プルダウン、タブ、一覧行をクリックする
6. Canvas、リモートデスクトップ、独自描画アプリなどUI Automationで要素を公開しない画面もクリックする
7. 記録を停止して取り込む
8. UI Automationで対象を取得できた操作は、リンクやボタン等の輪郭へ赤枠が付くことを確認する
9. 対象を取得できない操作は、全画面ではなくクリック位置の小さな枠になることを確認する
10. クリックから次の操作までの待ち時間が実用上増えていないことを確認する

## 入力と手動黒塗りの確認

1. 文字が見えてよい入力欄へテスト文字を入力し、少し待ってから次の操作へ進む
2. 入力手順の画像に入力後の文字が残り、入力欄へ赤枠が付くことを確認する
3. パスワード等の隠したい値は実データを使わず、架空の文字列で確認する
4. 取り込み後に対象手順の「画像を編集」を開く
5. 「黒塗り」を選び、隠したい文字部分だけをドラッグする
6. 編集画面、Excel出力、HTML出力で黒塗りが反映されることを確認する
7. `events.jsonl` と `project.json` に押したキーの文字列そのものが保存されていないことを確認する

## 修正内容

- クリック点に加えて周辺8点をUI Automationへ再照会
- Control ViewとRaw Viewの両方で最大12階層の親を確認
- 表示中の標準操作コントロールを条件検索し、256兄弟の上限と単一枝探索を廃止
- UI Automationで対象を取得できない場合は56×36ピクセルのクリック位置枠へフォールバック
- 入力欄の自動黒塗りを廃止し、入力後の表示をスクリーンショットへ残す
- 機密箇所は既存の非破壊画像編集から手動で黒塗り
- 配布版数をv0.32.9へ更新
